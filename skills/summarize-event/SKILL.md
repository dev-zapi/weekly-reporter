---
name: summarize-event
description: Summarize previous work items and log them into the weekly-reporter timeline.
---

Summarize the work done since the last summary or session start into one single-line plain-text event. Distill rather than transcribe: the timeline's reader needs the business core, not a blow-by-blow, so keep what shipped, what got fixed, or what was decided and its result. Simplify the rest — drop routine process steps, dead ends, and side observations, and group related minor items into one accomplishment instead of enumerating each. First query recent timeline events (via the timeline-events skill) to see what is already logged and to match their language and style. Name the project or repo the work happened in — the timeline spans many projects — and include concrete evidence such as commit hashes, ADR or test numbers. Keep the event content free of tags by default. Alongside the preview, list a few tags you would recommend (outside the event content) and ask the user to choose: A — no tags, B — the recommended tags, C — tags they type in. Write tags into the content only on a B or C choice or any other explicit request; when added, place them inline at the end of the line, separated by whitespace. Note the app's parsing rules: it recognizes `#word` tokens only at the start of the line or after whitespace, and only before whitespace or end-of-line, so a tag glued to preceding punctuation (e.g. 。#tag) is silently lost, and conversely any incidental `#word` in the text becomes a tag unless quoted ("#tag"). Event references use `@` plus a pure numeric id (`@6991`) with the same boundaries — `@6991，` or `（见@6991）` is silently plain text. When a summarized item continues, fixes, or verifies an event already on the timeline, prefer `@id` over vague prose, taking the id from the query above and using only ids that appeared in its output. References are ordinary content, not an attachment: they ride the normal preview and need no separate A/B/C choice. Preview the line for user confirmation, submit only after approval, then invoke the "timeline-events" skill to create the event.
