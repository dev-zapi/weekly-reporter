# 工作台布局：body-cap rail（封顶主体+弹性栏）(2026-11-11)

所有带右栏的工作台页面原先共用一条 `minmax(0, 1fr) 350px` 栅格，但这条规则在七个 CSS 模块里各写一份，折叠断点七页七个值（780/900/960/1100）。这带来三个问题：中间主体没有宽度上限，窗口越宽正文行长越失控；右侧栏恒为 350px，窗口余出的空间与真实需求脱节；改一处布局要同步七处、行为还互不一致。本 ADR 固定以 **body-cap rail（封顶主体+弹性栏）** 统一两栏页面的空间分配。

**决策四要点：**

1. **栅格契约**：中间主体宽度封顶 1000px，右栏下限 380px 并随窗口弹性增长，窗口余量优先给右栏。两个数值是设计系统级 token（`--wr-body-max` / `--wr-rail-min`，与现有 `--wr-*` token 同源），全站一处定义、一处生效。
2. **组件承载**：由共享的 `WorkbenchLayout` 复合组件持有栅格与语义标签（`section` / `aside` 及 `aria-label`）；页面自有的 surface 层（背景、padding、min-height、出血边距）留在各页面模块。新接入的两栏页面一律复用该组件，不再手写栅格。
3. **断点统一**：两栏在 ≤960px 折叠为单栏；删除各页 1100px 的右栏 350→300 过渡档（弹性右栏使其失去意义）。
4. **范围限定**：只改 7 处带右栏的两栏栅格——时间线、周报列表、周报详情、新建周报、周期计划、模板编辑、周报页 AI 会话。单栏页（采集源、模板库、提示词、安全设置、登录）与移动端 ≤780px 既有行为一律不动。

右栏内容宽度按页面定制：时间线与周期计划用双列瀑布流，周报详情 Review gate 用双栏卡片，周报列表与 AI 会话的正文保持既有 72ch 行宽。

## Considered Options

三变体原型在时间线、周报列表、周报详情三页实测比对后选定 C：

- **A 硬上限右栏全吃**：给中栏设上限，把余量全部推给右栏且右栏不设下限。宽屏下辅助内容被拉成大片空白，窄窗口又挤压主体，空间分配依旧失衡。
- **B 双双限居中**：中栏与右栏都设上限，整体居中、两侧留白。正文可读，但右栏在大屏上不再增长，辅助面板的可用宽度反而回退。
- **C 保行宽（取此方案）**：中栏封顶保住行长，右栏设下限并吃满余量。既不让正文变成横贯屏幕的长句，也让大屏上的辅助面板真正受益；窄窗口由 380px 下限保住右栏可用性。

另有三项备选被弃用：

- **维持固定 350px 右栏、只加中栏上限**：正文可读，但宽屏余量浪费在留白上，右栏在大屏仍是窄条。
- **各页保留自己的断点、只统一栅格数值**：收敛了一半，七页仍可能再次漂移，不符合「一处定义」的目标。
- **让用户可调封顶值与下限值**：单人工作台没有这个需求，偏好持久化与 UI 开关的复杂度大于收益；两个值保持为全局 token。

## Consequences

- 时间线与周报详情在 781–960px 窗口由两栏变单栏（原折叠点为 780px）；AI 会话的两栏区间从 ≥1100 收窄为 ≥961。这些行为变化在决策时已明确接受，并由 e2e 宽度契约断言守护。
- 时间线自动加载的宽屏媒体查询同步从 781px 改为 961px——该行为本属两栏布局，折叠后不应继续在单栏里追加内容。
- 周报页 1500px 总上限解除，内容模式与 AI chat 模式同享；generation 模块内部既有的行宽控制（createPanel 居中、气泡宽度、assistantBody / proposalDocument 的 72ch）不变。
- 7 份重复栅格收敛到一个组件与两个 token，后续调整封顶值或断点只改一处；新页面接入两栏布局时复用 `WorkbenchLayout`，不会再长出第八份手写栅格。
- 单栏页、登录页与移动端 ≤780px 行为不变；原型的浮动切换条、测量属性与变体开关不进入生产代码，三变体原型归档在 throwaway 分支 `prototype/body-cap-rail` 供考古。
