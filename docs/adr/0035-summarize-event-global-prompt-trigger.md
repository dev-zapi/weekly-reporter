# 全局 CLAUDE.md 首次触发指令：summarize-event 会话内强制提议 (2026-11-13)

summarize-event 的提议义务写在 skill description 里——每次会话常驻上下文的软约束，含完整节奏规则。实际失效模式是**会中遗忘**：description 在长上下文膨胀中被稀释，模型做完第三件事也想不起来提议。全局 `~/.claude/CLAUDE.md` 每次会话启动时注入，用一段短小的硬性指令（"必须"级措辞 + 唯一明确触发点）补上这个执行缺口。本 ADR 固定该指令的文本、措辞原则与边界。

**决策要点：**

1. **常设指令放用户级 `~/.claude/CLAUDE.md`**（跨项目生效）。前提成立：技能以 `~/.claude/skills/summarize-event` → `~/.agents/skills/` 符号链接全局安装。已于 2026-11-13 手工贴入，上线文本（抄录为契约，含标题行）：

   > # 工作记录
   >
   > 会话中完整做完第一件工作（功能落地、bug 修复、决策定案、PR 合并等）后，必须主动调用 `summarize-event` 技能提议记录该成果；此后何时再次提议、如何提问、何时停止，一律以技能自身规则为准。若当前环境未安装该技能，静默跳过，不要向用户提及本条。

2. **只规定一个硬触发点**：会话内第一件完整做完的工作之后必须调用技能提议。后续全部节奏——约三件未记录强制提议、换项目前、会末兜底、skip 全停、四选项话术——以 SKILL.md 为唯一事实源，指令一句"以技能自身规则为准"整体委托，不复述任何细节。
3. **提议而非静默记录**：preview-first 契约不变，direct-send 仍仅由用户口头触发（"直接发送"等）。默认跳过确认的 auto 模式明确否决——无人值守的价值抵不过它破坏「用户确认后创建」的核心契约。
4. **技能缺失环境静默跳过**（远程/未同步 `~/.claude` 的机器），指令自带此句，不向用户复述、不产生缺技能报错噪音。
5. **与 skill description 的分工**：description 管会中节奏规则且是唯一事实源；本指令只管第一触发点与"必须"级强制性。两条路径收敛到技能既定的同一四选项交互（now / not yet / skip / end）。

## Considered Options

- **`claude --append-system-prompt`**：仅单次启动生效、需每次传参，无法常设——否决。
- **SessionStart 钩子注入同一指令**：同为上下文注入且时序更确定，但多一份脚本与 `settings.json` 接线面；且启动时点本身无话可记，触发点必须绑定"工作完成"而非"会话开始"，注入时点与触发时点的错位对两者一样——v1 取零件更少的 CLAUDE.md，钩子留作 v2 候选。
- **动态 SessionStart 钩子（比对最后事件 vs 最近 commit，有漏记才提醒）**：需要 wrp 查询加 git 比对的脚本与缓存，机器更多、维护面更大——留 v2 候选。
- **SKILL.md 加 auto 模式默认 direct-send**：无人值守但破坏 preview-first——否决。
- **指令内复述节奏规则**（三件阈值、会末、skip）：制造第二事实源，SKILL.md 演进时必漂移——否决，改为整体委托。

## Consequences

- `~/.claude/CLAUDE.md` 是机器本地状态，不入库；本 ADR 是该文本的抄录源与变更记录，改文本需同步修订此处，保证契约文本在库内有落点。
- 所有项目的每个会话固定付出约一小段 token 的注入成本，换取每次启动一次的强制性注意力；这是用常驻成本换软约束合规率的明确取舍。
- 文本刻意不含节奏细节，SKILL.md 正常演进时无需改动本指令；仅当技能的四选项/提议模型发生根本变化时才需修订（新 ADR 或改文）。
- 语言取中文而非与全局配置其余英文一致：用户工作语言、措辞精度优先；英文变体在决策会话中起草过，未采用。
